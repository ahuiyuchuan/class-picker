# 实现与维护说明

作者：ahui

## 模块与数据流

Python 桌面入口 `backend/main.py` 创建 WebView2 窗口并向前端暴露白名单数据桥接；`backend/storage.py` 负责 SQLite、导入导出及备份恢复。Vue 页面通过 `frontend/src/data.js` 调用桥接并接收状态快照。

`backend/data_lock.py` 协调同一 Windows 会话下相同数据目录的进程访问；`backend/window_transition.py` 在窗口过渡期间合并布局和重绘。窗口操作在 GUI 线程执行，过渡异常也须恢复布局、重绘与 DWM 属性。

## 课堂与窗口

- 随机抽样由 Python 执行，前端姓名滚动仅用于展示，不影响抽取概率。动画候选排除停用、临时排除及无放回模式已抽过的学生。
- 每次抽取按当次人数创建槽位，结果、统计、最近记录在动画结束后一起发布；请求失败清理动画并保留上次结果和当前配置。后端已提交的结果可在重启后恢复。
- 最大化使用当前显示器工作区保留任务栏，全屏使用整个屏幕。进入全屏保存普通窗口矩形与原最大化状态，退出时还原；失效显示器位置回退到当前工作区。
- 全屏管理页占满可用高度，返回课堂保持全屏。F11/Esc 适用于子页；弹窗、菜单和下拉优先处理自己的按键，空格抽取仅在课堂生效。

## 名单规则

姓名必填，学号选填，两者最多 60 字符；空学号保存为 NULL，不生成编号，不以内部 ID 代替。非空学号在班内唯一并保留前导零。

点击添加学生会追加一行草稿，同班最多 100 行。全空行跳过，非空行整批校验后事务提交；错误保留输入，不部分保存。草稿按班级隔离，仅在内存保存，自定义关闭或返回时提示放弃未保存内容；强制退出、断电不保证恢复。

筛选后的全选只作用于可见行，隐藏行选择保留。排序在搜索、行编辑、新增草稿或保存期间禁用，首尾越界不操作。学生排序不改变学号、抽取概率或历史快照。

## 数据桥接约定

桥接入口为 `data(action, payload)`，action 必须为文本，payload 为对象；后端仅接受已实现的白名单动作。调用形式和错误处理以 `frontend/src/data.js` 为准。

| 动作 | 主要参数与约束 | 成功结果 |
| --- | --- | --- |
| `load` | 无业务参数 | 完整状态快照 |
| `draw` | `class_id`、`request`；请求标识用于幂等校验 | 抽取后的完整快照 |
| `add_students` | `class_id`、`rows`；每批 1—100 条，每条包含 `name`、可空 `no`、布尔 `enabled`（默认 true） | 提交后的完整快照 |
| `move_student` | `class_id`、`id`、`direction`；方向仅为整数 -1 或 1，学生须属于指定班级 | 排序后的完整快照 |
| `history_page` | `class_id`、`page`；页码默认 1，须为正整数 | `{records, total, page}`，超过末页归入末页 |

完整快照固定五次查询，各班首页历史最多读取最近 50 次；历史页面每页 20 次，不受该快照上限影响。记录包含抽取时的姓名和学号快照，空学号不显示占位编号。切班时丢弃过期响应。

## 文件导入导出

导入支持 XLSX、XLS、CSV。读取全部工作表（包括隐藏表、空表），CSV 作为一张工作表；默认勾选第一张非空表。勾选决定是否提交，点击表名只切换预览，不改变选择。所选表按读取结果的枚举顺序合并到当前班级，不自动创建班级。

每张表独立保存列映射和数据起始行；姓名列默认 A 列、必选，学号列默认 `null` 表示不读取，界面无需输入 0。列下拉显示字母与表头/样例；起始行默认 2，可设为 1 表示无表头。勾选多张表时显示「将此配置应用到其他已选表」，仅复制映射和起始行到当前表以外的已选表，不改变勾选状态；目标表仍逐一校验范围。先按原工作表行号截取，再忽略空行；错误保留 Sheet 和原始行/单元格位置，跨表重复同时指出两处来源。

导入弹窗采用左侧工作表、右侧配置与预览、固定底部摘要及操作栏。文件导入与粘贴预览都支持完整数据分页，每页固定 50 条，支持前后翻页和输入页码；修改映射、数据或切换工作表后回到首页。表格保留原始行号，完全空行仍按既有规则忽略。分页仅限制渲染数量，不截断整批校验、人数统计或提交内容。结构化问题保存 `sheet`、`row`、`message`，配置和全局问题的 `row` 为 `null`；「查看问题」按位置切表、翻页并聚焦错误行，不通过错误文案反解位置。多处问题可逐个查看，未选表的问题不阻止已选表提交。页码输入按 Enter 只完成页码切换，不提交名单。

原文件最多 10 MiB，每表最多 10001 行（含表头）、50 列；XLSX 声明解压总量最多 64 MiB，解析时检查实际行列，不依赖工作表尺寸声明。多表合计每次最多导入 10000 人；未勾选任何表或所选表无有效数据时禁止提交。未选工作表仍受文件解析大小限制。

文件导入预览提供行内编辑及移除，粘贴导入继续直接修改文本。行内草稿一次一行，保存校验姓名必填及两字段 60 字上限；重复学号仍由整批校验阻止提交。手填学号可用于默认不读取学号的映射。修正保存在每张表 `edits` 中，按原始行号分别记录实际修改的姓名、学号；切换任意列或起始行均不删除修正，未修改字段从新列读取，显式空学号也优先保留。仅已修正字段覆盖对应公式缓存问题，未修改字段的问题仍须处理，不写原文件或数据库。移除记录原行号，不重排行号，并支持按后进先出逐次撤销；全表移除后仍按空表禁止导入。编辑和移除保留当前页，末页消失时收敛到最后一页。草稿期间禁止切表、翻页、列配置和提交，取消编辑恢复原值；关闭弹窗丢弃本次全部预览修改，无数据迁移，数据库保持 v2。

XLSX 使用 openpyxl 的 `data_only=True` 读取缓存，另一个只读视图仅识别缺少缓存的公式；XLS 由 xlrd 读取缓存，不执行公式，不访问公式中的外部链接。CSV 按 UTF-8 BOM/GB18030 读取原始文本，公式样文本不计算。缺失的 XLSX 公式结果和 Excel 错误单元格保留为 `{issue: 提示}`；只有选择该列且位于导入行范围内时才阻止提交。合法空字符串缓存按空白处理，姓名仍必填；xlrd 无法区分缺失公式缓存与普通空文本，因此 XLS 的空缓存按普通空值校验。不读取的列有问题不阻止导入。

普通单元格转为文本；数值零不会丢失，整数不附带 `.0`，纯零整数格式（例如 `00000`）保留前导零，布尔值用 `TRUE/FALSE`，日期/时间采用 ISO 文本。其他自定义格式使用底层值，不模拟 WPS 的完整格式渲染，也不重新计算过期缓存。

`read_file`/`choose_import` 仍返回 `{工作表名: 二维数组}`，新增单元格问题对象；前后端须配套更新，旧前端不理解问题对象。前端 `rosterImport.js` 负责预览与跨表校验，提交时只传 `{name, no}`；`import` 写入协议不变，最终校验和事务仍由后端执行。追加检查当前班级学号，替换只检查整批内部学号；替换只执行一次，清空本轮进度、保留历史并先备份，失败整批回滚。数据库无迁移；回退代码时同时回退并重建前端，已导入数据仍兼容 v2。

导出与模板均为 XLSX，姓名和学号写为文本。模板首行为“姓名、学号”，示例为张三（202609201940）、李四（202609201941）、王五（202609201942）。

## 事务、恢复与兼容性

写入使用参数绑定与 SQLite 写事务；抽取在取得写锁后检查请求标识，避免并发重复抽取。进程互斥等待最多 5 秒，超时提示重试，句柄在外层操作结束时释放。其他 Windows 会话、旧程序或外部数据库工具不遵循此锁。

当前数据库结构为 v2，学生 position 保存名单顺序；从 v1 升级前生成备份。恢复会在临时副本中校验数据并升级，拒绝未知表、视图及业务触发器，重建应用排序触发器和索引，通过后替换正式库。校验与复制源备份使用同一读取事务。

备份恢复前应关闭不遵循互斥的访问者。回退到不支持当前结构的程序必须使用升级前备份，不能将新库直接交给旧程序；回退副本不包含升级后的修改。

## 检查与限制

安装、构建及测试命令见 [开发与验证指南](development.md)。Python 单元测试验证事务、边界、缓存结果和导入兼容；Node 内置测试验证多表独立映射、原始行号、跨表重复、可选学号和人数限制。真实 WebView2 回归验证多表选择与提交、名单、关于、抽取人数、窗口状态与全屏页面组合。GUI 测试使用隔离数据，不得指向正式名单。

多显示器热插拔、混合物理 DPI 及跨显卡逐帧表现需要对应设备验证；页面缩放与模拟失效矩形不能替代这些硬件场景。不要将通过已有测试表述为覆盖全部运行环境。
